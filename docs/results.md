# Results

First full run, November 2026. Every number here is regenerated by the commands in the README
("Reproducing the results"); the figures are written to `results/` and are not in git.

**Setup.** 24-PRB carrier, 30 kHz SCS, PUSCH with QPSK and LDPC (MCS 5), one front-loaded DMRS
symbol, random allocation of 6–24 PRBs, TDL-A (100 ns) and TDL-C (300 ns), up to 3 m/s. Gaussian
jammer on a block of 2–12 PRBs anywhere on the carrier. JSR is per jammed resource element,
relative to the UE's data-RE energy (DMRS REs carry 3 dB more). Training: 40 000 slots; validation:
5 000; test: 31 000 (grid over JSR −15…+9 dB, SNR drawn from 5–25 dB); scheduling-aware test:
16 200. All splits use separate seed ranges.

## 1. What each attack does to the link

`results/ber_bler/ber_bler_{A,C}.pdf`. SNR 15 dB, the jammer covers the whole allocation.

| Attack | 50% BLER, TDL-A: JSR / slot energy ratio | 50% BLER, TDL-C: JSR / slot energy ratio |
| --- | --- | --- |
| Pilot | +4.1 dB / **−7.0 dB** | +3.7 dB / **−7.4 dB** |
| Data | −2.7 dB / −2.7 dB | −3.2 dB / −3.2 dB |
| Partial-band | −3.7 dB / −3.4 dB | −4.0 dB / −3.6 dB |

Per resource element, pilot jamming needs a higher JSR, but it only occupies 1 of 14 symbols. Per
unit of jammer energy it is the most efficient attack: it reaches 50% BLER with about 4 dB less
energy than data or partial-band jamming, in line with Clancy's pilot-jamming result. Without a
jammer the BLER is 0 at this SNR. Points below BLER ≈ 2·10⁻³ rest on one or two block errors
(1 280 slots per point).

## 2. What the features see

`results/feature_maps.pdf`. Mean values over the scheduled cells, JSR 0 dB, SNR 20 dB, jammer on
the whole allocation (linear, noise-normalized):

| Condition | DMRS residual R | EVM E (data cells) | Power P |
| --- | --- | --- | --- |
| No jammer | 1.0 | 1.3 | 105 |
| Pilot | **108** | 15 (wrong symbols) | 105 (high only on the DMRS row) |
| Data | 1.0 (blind) | **56** | **193** |
| Partial-band | **108** | **66** | **200** |

This matches Table 2 of the proposal. Pilot jamming shows up in the EVM of the *data* symbols,
which is why EVM alone reports it at the wrong symbols. One correction to Table 2: without
jamming, normalized EVM is about 1 only at moderate SNR. It rises to about 2 at 25 dB and about 4
at 30 dB on TDL-C, because the LS estimator's error variance leaves out interpolation error and
channel aging. The residual stays at 1.0 at every SNR, because the UE's own channel lies inside
the delay subspace.

## 3. Detection: Pd at 1% per-cell false alarm

`results/eval/test_pd_vs_jsr_{scheduled,all}.pdf`. Thresholds come from the validation set; the
false-alarm rate measured on the test set is 1.1–1.3% for every detector. Pd over the jammed
cells inside the allocation, TDL-A and TDL-C together:

| Attack | Detector | JSR −15 dB | −9 dB | −3 dB | +3 dB |
| --- | --- | --- | --- | --- | --- |
| Pilot | **U-Net, P+R+E** | **0.61** | **0.86** | **0.97** | 0.99 |
| | U-Net, P+E | 0.42 | 0.81 | 0.95 | 0.99 |
| | U-Net, power only | 0.30 | 0.65 | 0.89 | 0.96 |
| | U-Net, EVM only | 0.15 | 0.44 | 0.69 | 0.83 |
| | Residual threshold | 0.11 | 0.34 | 0.63 | 0.87 |
| | EVM threshold | 0 | 0 | 0 | 0 |
| Data | **U-Net, P+R+E** | **0.75** | **0.96** | 0.99 | 1.00 |
| | U-Net, P+E | 0.66 | 0.95 | 0.99 | 1.00 |
| | U-Net, power only | 0.51 | 0.82 | 0.95 | 0.99 |
| | U-Net, EVM only | 0.44 | 0.77 | 0.93 | 0.99 |
| | EVM threshold | 0 | 0.09 | 0.28 | 0.51 |
| | Residual threshold | 0 | 0 | 0 | 0 |

Partial-band jamming behaves like data jamming (P+R+E: 0.78 / 0.96 / 0.99 / 1.00).

Cell-level F1 at the same thresholds:

| Detector | Pilot | Data | Partial | All slots |
| --- | --- | --- | --- | --- |
| **U-Net, P+R+E** | **0.835** | **0.956** | **0.959** | **0.951** |
| U-Net, P+E | 0.784 | 0.949 | 0.956 | 0.944 |
| U-Net, power only | 0.832 | 0.921 | 0.917 | 0.914 |
| U-Net, EVM only | 0.440 | 0.806 | 0.793 | 0.783 |
| EVM threshold | 0 | 0.389 | 0.381 | 0.363 |
| Residual threshold | 0.569 | 0 | 0.060 | 0.058 |

**Reading.** The DMRS residual is what makes weak pilot jamming detectable: at −15 dB it raises
Pd from 0.42 (P+E) to 0.61. The two threshold baselines each see only half of the problem: the
EVM threshold cannot score the DMRS symbol, and the residual threshold is blind to data jamming.
Power alone does well when the jammed block stands out against unjammed PRBs, and worse when it
does not (next section).

## 4. Robustness: scheduling-aware jammer

`results/eval/sched_pd_vs_jsr_scheduled.pdf`. The jammer hits exactly the scheduled PRBs. This
attacker was never seen in training.

| Detector | F1 all | Pd pilot, −15 dB | Pd data, −15 dB |
| --- | --- | --- | --- |
| **U-Net, P+R+E** | **0.948** | **0.59** | **0.60** |
| U-Net, P+E | 0.946 | 0.34 | 0.58 |
| U-Net, power only | 0.896 | 0.24 | 0.43 |
| U-Net, EVM only | 0.752 | 0.05 | 0.23 |

When the whole allocation is jammed, there is no clean neighbouring PRB to compare against. Power
and EVM lose part of their contrast; the residual is an absolute measure and does not. The fused
detector keeps its pilot-attack Pd (0.61 → 0.59) while P+E drops from 0.42 to 0.34.

## 5. Size and latency

`results/latency.csv`. One slot, one CPU thread, MacBook Pro M1 Pro.

| | Value |
| --- | --- |
| U-Net parameters | 66 553 (fused) |
| Feature extraction from receiver outputs | 0.26 ms |
| U-Net forward pass | 0.48 ms |
| **Total** | **0.75 ms** |

With PyTorch's default eight threads the U-Net takes about 1.3 ms; for an input this small the
thread pool only adds overhead.

## Caveats before these go into the paper

- These numbers were produced before the per-pilot residual normalization (issue #1), which
  removed a ~1 dB low bias of R on the two edge PRBs of each allocation. Regenerate the
  datasets and retrain before using them in the paper; changes should be small.
- One training seed per variant. P+R+E and P+E differ by 0.007 in overall F1; that gap is not
  established without several seeds. The pilot-attack gap (Pd 0.61 vs 0.42 at −15 dB, F1 0.835 vs
  0.784) is much larger.
- Each Pd point averages over SNR 5–25 dB. Fixed-SNR curves can be made by filtering on `snr_db`.
- 15 training epochs (validation loss flattened after about 8–12).
- Only 190 different allocations exist, so test allocations repeat training ones; channel
  realizations and jammer draws do not.
