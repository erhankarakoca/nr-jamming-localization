# Showcase site and new paper figures: design

20 November 2026. Status: approved (merged in #11).

## Intent

The project should be seen working, not only described. A public project page on GitHub Pages
lets a reader of the paper, a reviewer or a course audience watch a jammed slot go through the
receiver. They can inspect what each detector flags and see how the protected receiver changes
the constellation and the decoding outcome. The same material improves the paper:

- a figure that shows *when* detection and mitigation happen in a slot;
- clearer versions of Fig. 3 (the DMRS residual) and Fig. 6 (example maps), which the author does
  not like.

## Goals

1. **Paper figures** (one exporter feeds all of them):
   - a timing figure for the system model;
   - a redesigned Fig. 3 (residual explainer);
   - a redesigned Fig. 6 (example maps plus a population comparison).
2. **A static site on GitHub Pages**, served from this (public) repository, with five parts:
   - **one slot, step by step:** an animated walk through receive, features, map, protected decoding;
   - **explore a slot:** pick a scenario, click a cell, see its features, every detector's decision,
     the constellation of its PRB under each receiver, and the CRC;
   - **constellation gallery:** the scenarios below, standard against protected receiver;
   - **animations:** a hopping and a pulsed jammer over the 14 symbols with the map following them,
     and the residual as the JSR grows;
   - **results:** the paper's curves and tables (detection, margin, recovery, matched false alarms),
     interactive and downloadable, with their failure cases.
3. Everything shown comes from the real simulator: exported once, reproducible from code + seeds.

## Non-goals

- No in-browser simulation of the receiver. Sionna cannot run in a browser, and a toy simulator
  would give numbers that differ from the paper.
- No server, accounts or analytics.
- No new experiments for the paper beyond what the figures need.

## Anti-goals (a failure even if it works)

- **A number on the site that differs from the paper,** or that is shown without its population
  (which split, which thresholds, which JSR).
- **Cherry-picked examples** presented as typical. Example slots are chosen by a stated rule, and
  the failure cases (pilot spoofing, whole-allocation pilot jamming with the estimated noise power,
  hopping against the block-trained U-Net) are shown too.
- **A timing picture that claims a real-time receiver.** Detection uses the whole slot after
  equalization, and mitigation re-processes the same buffered slot. Nothing is "detected at symbol
  2", and the detection margin (a JSR difference in dB) is never drawn as elapsed time.
- **Mentions of AI tools** anywhere in tracked files or commits (project rule).

## Constraints

- **Project conventions (README, CLAUDE-style rules):**
  - code in `src/jamloc/`, tests in `tests/`, runs unchanged on CPU and CUDA and on Windows, Linux
    and macOS;
  - pathlib, utf-8;
  - generated data never committed to `main`.
- **The trained checkpoints are not in git.** The export must therefore run locally (or on Colab).
  GitHub Actions cannot regenerate the data.
- **The site is public;** the repository is public.
- **External JavaScript:** only pinned versions from a CDN (Plotly for curves). Otherwise plain
  HTML, CSS and JS modules, with no build step and no Node toolchain.
- **Size:** about 5 MB of data in total, about 200 kB per example slot, loaded on demand.
- **Paper figures** follow the paper's style (`jamloc.plotting.paper_style`, IEEE column/two-column
  widths) and the writing guide.

## Approaches considered

| Approach | Trade-off | Decision |
| --- | --- | --- |
| **A. Static pages generated by the project** (`python -m jamloc.site`): HTML + JS modules + JSON data; SVG grids, canvas constellations, Plotly curves | No new toolchain, reproducible, full control of the interactions; more hand-written layout | **Chosen by the author** |
| B. Quarto site | Polished article pages with equations; another toolchain, harder custom interactions (cell to decoder) | Rejected |
| C. JS framework (Svelte / Observable) | Richest interactivity; a Node toolchain beside Python, too much to maintain | Rejected |

Hosting:

- Chosen: GitHub Pages from this repository after making it public. Free for public
  repositories.
- Rejected: Pages from a private repository (needs GitHub Pro), and a separate site repository
  (two repositories to keep in sync).

## Design

### 1. Exporter (`jamloc.site.export`)

A list of named **cases**, each fully specified:

- channel, SNR, attack, JSR;
- jammer variant: nominal, pulsed, hopping, spoofing;
- noise mode: true or estimated per slot;
- simulation seed and detector training seed.

For each case the exporter:

1. Simulates one batch of slots on the CPU with the case's seed.
2. Picks the example slot by a documented rule. The default: the slot whose U-Net hit rate on the
   jammed cells is the median of the batch. The rule and the batch statistic are stored with the
   case.
3. Runs, on the same received grid:
   - the detectors (U-Net P+R+E, U-Net P+E, block test, EVM threshold, residual threshold), with
     their validation thresholds;
   - the receivers: standard, map-aware soft and hard with the U-Net map, soft with the true map.

It stores per case, in one compact JSON file, with floats rounded:

- **metadata:**
  - all parameters and seeds;
  - the device;
  - the git commit;
  - the threshold sources;
  - the selection rule.
- **24 x 14 grids:**
  - the feature maps P, R, E in dB;
  - the allocation;
  - the true map;
  - each detector's scores and decisions;
  - unscored cells marked as such.
- **per PRB:** `R_b` and its analytic threshold.
- **per pilot (complex):** the LS estimate and its projection, for the residual views.
- **per receiver:**
  - the equalized symbols of the allocation (complex, about 1 900 points);
  - the per-cell mean absolute LLR;
  - the CRC result.

A `manifest.json` lists the cases and their files. The output goes to the results tree
(`results_dir()/site/data/`), never to `main`.

**Cases (first set):**

| # | Scenario | Purpose |
| --- | --- | --- |
| 1 | Benign, TDL-C, 15 dB | Reference constellation and maps |
| 2 | Pilot jamming, +3 dB | The cloud of the affected PRBs rotates and spreads (bad channel estimate); protection restores it; EVM misplaces the attack |
| 3 | Pilot jamming, -12 dB | Weak pilot jamming: what the residual adds |
| 4 | Data jamming, +3 dB | Only jammed cells scatter; protection shrinks their LLRs |
| 5 | Partial-band, +3 dB | Both effects |
| 6 | Hopping, +9 dB | Per-cell vs per-PRB map; block-trained vs mixed-attack U-Net |
| 7 | Pulsed, +9 dB | Support changing per symbol |
| 8 | Pilot spoofing, -9 dB | Residual blind, training with spoofing fixes placement |
| 9 | Whole-allocation pilot jamming, estimated noise, +3 dB | Failure case of the noise estimate |
| 10 | JSR sweep of one channel realization, pilot jamming, -15 to +9 dB | Residual-vs-JSR animation |

### 2. Paper figures (`jamloc.experiments.figures`, from exporter cases)

- **Timing figure (system model, one column).**
  - The top strip is the physical axis: slot `n` (0.5 ms), symbols 0-13, DMRS at 2, with the
    received grid available at the end of the slot.
  - The lower strip is labeled "processing order (not to scale)" and has two phases:
    1. detect: estimation, equalization, P/R/E, U-Net, map;
    2. mitigate and decode the same slot: pilot re-weighting, re-equalization, LLR scaling, LDPC,
       CRC.
  - The measured CPU time of the detection stage (0.48-0.68 ms) goes in the caption only, with its
    scope.
  - Drawn with matplotlib, so it is reproducible and consistent with the other figures.
- **Fig. 3, residual from pilots to PRBs (one column).** Case 2 at 20 dB SNR, the paired
  realization of the current figure.
  - Top: the squared residual of each of the 72 pilots, `|h~_p - (U U^H h~)_p|^2`, with PRB
    dividers and one PRB bracketed ("six pilots of PRB 11").
  - Bottom: `10 log10 R_b`, the benign slot as open circles and the jammed slot as filled squares,
    with the position-dependent analytic 1% threshold as a step line.
  - The jammed block is shaded in both panels, and the leaking clean neighbor is labeled.
- **Fig. 6, where a detector puts the alarm (two columns).**
  - Left two-thirds: three aligned maps of case 2: injected interference, EVM threshold flags,
    U-Net P+R+E flags. The truth is outlined, there is one fill for flags, unscored cells are
    hatched, and the DMRS symbol is marked.
  - Right: a dot plot of the share of weak-pilot (-12 dB) DMRS cells found by each detector over
    the eligible test slots, with 95% intervals.
  - Each panel names its JSR and denominator.
  - The current 4 x 6 grid moves to the site's explorer.

### 3. Site (`site/` sources, `jamloc.site.build`, `jamloc.site.deploy`)

- **Sources** (hand-written HTML/CSS/JS, tracked) live in `site/`.
- **`python -m jamloc.site build`** combines them with the exported data and the paper's result
  CSVs into `results_dir()/site/build/`.
- **`python -m jamloc.site deploy`** pushes the build to the `gh-pages` branch. Pages serves that
  branch, and `main` never holds generated files.
- **Pages:**
  - Home: a short summary, the key figure, links to code and paper, how to cite.
  - One slot, step by step: a stepper with play/pause over case 2. Steps: grid with injected
    jamming, power, residual, EVM, map vs truth, constellation standard vs protected, CRC.
  - Explore: a case selector, grid layers (features, truth, each detector), click a cell for its
    values and decisions, the PRB's constellation for each receiver, and the CRCs.
  - Constellations: cases 1-9 side by side, standard vs protected; point opacity shows LLR
    reliability.
  - Animations: the hopping and pulsed jammers stepping through the symbols with the maps, and the
    residual-vs-JSR slider (case 10).
  - Results: Pd vs JSR, margin vs SNR with intervals, the recovery table with paired intervals and
    the matched false alarms, each with its population and a CSV download; the failure cases.
- **Shared look:** the paper's palette, readable on a phone, light background.

### 4. Tests

- **Exporter:** one tiny case, checking the schema and that the receivers saw the same received
  grid.
- **Build:** every page is generated, references existing data files, and has no unpinned scripts.
- **Figures:** they render from a small case.

## Left to the builder

- exact JSON field names and rounding;
- the visual style within the paper's palette;
- the page copy (plain prose per `docs/writing-guide.md`);
- the animation frame counts and timing;
- how the slot-selection statistic is computed for each case;
- the details of the deploy command (orphan `gh-pages` branch, `.nojekyll`).

## Questions from the builder check, and the calls made

An independent read of this document raised seven questions. The designer's calls (marked) settle
six of them; one is the author's.

1. **Fig. 3 slot.** *Call:* keep the paper's existing paired realization (TDL-C, 20 dB SNR, 0 dB
   JSR, benign and jammed sharing channel and noise) as a separate paper case `fig3`. Case 2 stays
   at +3 dB for the site.
2. **Fig. 6 population.** *Call:* use the population of the paper's detection results (scheduled
   jammed DMRS cells at the lowest JSR, three seeds, the existing batch-bootstrap intervals in
   `results/intervals/`), not the old figure's filtered subset, so the numbers match the paper.
3. **Maps decoded in the hopping and spoofing cases.** *Call:* run a receiver pass for every map
   the case compares:
   - hopping: the block-trained U-Net, the mixed-attack U-Net, the true map per PRB and the exact
     true map;
   - spoofing: the nominal U-Net and the U-Net trained with spoofing in the mix.
4. **Detectors in the estimated-noise case.** *Call:* only the detectors trained or calibrated on
   the estimate (the fused U-Net of `train_nest`, and the block test and power test on `val_nest`).
   The others show "not available in this setting".
5. **Walkthrough outcome (settled: the designer's suggestion, the author left it open).** Should the step-by-step slot be the
   representative slot (where both receivers may decode), or a slot where protection turns a
   failed CRC into a pass, shown with how often that happens in the batch? The designer's
   suggestion: the representative slot, plus a second, clearly labeled slot where protection made
   the difference, with its frequency.
6. **Old Fig. 6 slots.** *Call:* not preserved. The explorer uses the new cases; the power-only
   U-Net stays available as a layer.
7. **LLR reliability.** *Call:* export |LLR| per point (one small number per point and receiver),
   so the opacity varies within a cell.
